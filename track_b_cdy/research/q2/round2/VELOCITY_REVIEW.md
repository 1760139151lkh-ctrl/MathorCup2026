# Q2 第二轮：速度定义与本地处理链

日期：2026-10-24（America/New_York）。本页是有界产品追溯；不修改原值、不估计触发阈值、不选择核心模型。机器条目见 `results/velocity_definition_chain.csv`，来源版本、实际阅读范围、UTC 和哈希见 `sources/velocity_source_register.json`。

## 可以采用的有限结论

1. **本地速度是背景统计场。** 直接读取原 NC：仅有 `x=145,y=138`，没有 time 维；`vx/vy` 属性明确写 2014—2024 年度分量的加权线性拟合、2018-01-01 时间截距；单位 `meter/year`。`v` 声明由分量模长获得；`v_amp` 是平均流向上的季节振幅，不能当单次事件速度。
2. **官方定义与本地说明语义相符，但尚不能认定原对象。** [NASA/JPL production 仓库固定代码](https://github.com/nasa-jpl/its_live_production/tree/8a39afbd8279d94c4b1d3e7b99b722527f66a85c)的 `itslive_composite.py` 默认 `v0Years=2014..2024`、`interceptDate=2018/01/01`；`itslive_mosaics_types.py` 对 `vx0/vy0/v0` 给出对应描述。本地字段名为 `vx/vy/v`，属性描述近似上述气候态字段，**映射仅属语义推断**，缺少生成脚本不能确认其实际改名来源或运行版本。
3. **顺序在官方 composite 层可以直接读到。** 代码 1012—1028 行对年度分量选定年份，调用误差加权线性拟合取得截距；1222—1315 行由气候态分量计算 `sqrt(vx0**2+vy0**2)`。这支持“先拟合分量、后合成模长”的该代码定义，不支持“v0 是各年度标量速度的简单平均”。没有执行或导入官方生产脚本。
4. **截距不是一次 2018 年实测，也不是保证每格均作双侧线性拟合。** 同一代码 1408—1489 行在截距两侧均有有效年度值时拟合，否则退回可用分量的加权均值并将趋势置 NaN。本地未带对应年度序列、误差、计数和趋势，不能识别本地每格是否使用了该退回分支，更不能将代码默认行为当本地生成事实。
5. **阶段 3 没有制造速度残差。** 已读 `prepare_spatial.py` 272—326 行和 `pipeline_report.json`：阶段 3 打开已有 NC、随坐标排序、核对 raw/decoded 相等；`vx/vy/v` 三者记录均为 true。它只导出 NC 的 DEM/mask，并把另一 DEM 双线性重投影到 NC 网格；没有重新生成或重采样速度、没有重算其模长。`source_manifest.json` 仅证明读取哪个文件，不能替代原始产品生成记录。

## 外部版本边界

本轮只保存 5 份官方正文，合计 **571,918 bytes**，没有下载 ITS_LIVE 栅格、datacube 或全球目录。四张 PDF 核读页是同一文档的本地渲染，另计于来源登记的派生文件，总保存量仍低于 2 MiB。

[NSIDC-0776 v2 用户指南](https://nsidc.org/sites/default/files/documents/user-guide/nsidc-0776-v002-userguide.pdf)的发布/更新均为 2025-07，其表 2、处理章节描述的是 2014—2022 气候态、120m 产品、2018 截距，且说明区域拼接会旋转分量到新地图坐标。该指南不能单独认证本地声明的 **ITS_LIVE v2.1 / 2014—2024** 发布版本。固定 NASA/JPL 当前源码的年份默认值与本地一致，仍缺本地原对象标识和运行记录，不能把“当前仓库代码可实现”写成“本地确由此提交生成”。

官方 S3 README 区分影像对、datacube、composite 和区域 mosaic，并说明 120m 网格；NC 的 30m 是供应方声明的重采样目标间距，不能据此称原生 30m 动态观测。原生所用对象/网格仍待追溯。

## 本地链核查与仍未知项

核查范围为给定 B 赛道全部文件名、速度子目录内容、共享脚本与已附来源文档；速度子目录仅有该 NC。`source_documentation.json` 只有高程变化说明、历史灾点元数据、DEM 元数据，未含速度生成说明。没有找到本 NC 的制作脚本或原 ITS_LIVE 对象标识；该结论仅对本仓库已交付材料成立，不声称外部不存在脚本。

| 环节 | 可直接证明 | 仍未知 |
|---|---|---|
| 官方 composite 定义 | 固定代码的年份、截距、分量拟合及模长步骤 | 是否为本地实际生产版本、每格退回分支 |
| 原生产品 → 本地 30m | NC 声明 ITS_LIVE v2.1 和 bilinear | 原对象 URL/版本/原生 CRS；裁剪、旋转、拼接、模长与双线性先后；掩膜/NoData、误差、精度处理 |
| 本地 NC → 阶段 3 | 已有 NC 读取、排序、raw/decoded 相等；未重新处理速度 | 无法反推供应方生成过程 |
| `v` 与 `hypot(vx,vy)` | 首轮已记录差异 | 插值、拼接、旋转、统计或其他因素分别贡献多少 |

直接引用首轮 `results/input_check.json`，**本轮未重算全表**：最大绝对残差 **0.4946554486149263 m/year**，中位数 **0.024470053252602875**，p95 **0.16701166226455771**，**7142/7152** 格超过 `1e-4 m/year` 算术筛查容差。该容差不代表观测误差、物理质量或触发阈值。

模长是非线性运算，通常“分量插值后取模长”不等于“先取模长再插值”；这只说明一个数学上可能的机制。**本次残差成因继续为 unknown**。同样，“先合成后平均”既未证明是本地步骤，也不能从官方气候态定义直接推成实际原因。没有将给定 v 替换为重算值。

- **可采用（角色限定）：** 可将三项原字段分别作为“供应方声明的历史背景统计量”进行探索，明确 30m 为重采样间距、质量与原链未认证、未取得源区事件值；原文件与哈希保持可追溯。

- **仍未知、对方向有关：** 本地 `spatial_ref` 是 EPSG:32645，但缺原生速度 CRS 和分量旋转记录。地图位置的 CRS 不能单独证明分量已正确旋转到目标坐标，故不能直接把本地 vx/vy 当已验收的 Q4 初始流向向量。
- **最小后续证据：** 先找回原产品精确对象 URL/版本/哈希和生成脚本或参数日志；只需与本区域有关的原生元数据、必要少量对应格点，核对年度/气候态字段映射、原/目标 CRS 及向量旋转、统计→拼接→模长→重采样顺序、掩膜/NoData、误差/计数。没有这些记录时本项以“背景可探索、原链/原因未知”结束，无需扩扫下载或联系作者。
